# 券数据字段说明（实测）

本文件记录 `mcd-mcp` 券相关接口的**真实返回结构**与已知的坑。
所有结论来自 2026-10 对线上接口的实际调用，不是推测。

---

## 一、三个必读接口

### 1. `available-coupons` — 可领取券

返回**极其有限**：只有券标题、状态、图片。

```text
- 优惠券标题：巧克力味厚松饼猪柳蛋套餐
  状态：已领取
  优惠券图片：<img src="..." />
```

**没有有效期，没有价格。**
→ 结论：本接口只能判断「有没有券可领」，要拿到可用信息必须**先领、再查卡包**。
→ 这就是流水线固定为 `available-coupons → auto-bind-coupons → query-my-coupons` 的原因。

### 2. `auto-bind-coupons` — 一键领取

无参数，系统自动领取用户当前可领的全部券。
返回信息不含券明细，**不能**用它当作数据源，领完仍需调 `query-my-coupons`。

### 3. `query-my-coupons` — 券包（唯一完整数据源）

参数：`page`（默认 1，最多 5 页）、`pageSize`（默认 200，最大 200）。

每张券的字段：

| 字段 | 示例 | 说明 |
|---|---|---|
| 券名 | `4折麦辣三件套券` | 营销文案，品类/折扣要从这里解析 |
| 优惠 | `¥4 (用券立享)` | **语义不固定，见坑 2** |
| 有效期 | `2026-10-10 00:00-2026-10-16 23:59 10:30-23:59` | 自由文本，**见坑 1** |
| 领取时间 | `3日前收到` / `今日收到` | 可用于识别新券 |
| 标签 | `到店专用` / `外送专用` | 决定可用渠道 |

---

## 二、三个必须处理的坑

### 坑 1：有效期是自由文本，格式不统一

实测至少 4 种形态：

| 形态 | 原文 |
|---|---|
| A 日期区间 + 每日时段（含跨天） | `2026-09-24 10:30-2026-12-31 23:59 10:30-23:59 00:00-04:59` |
| B 纯日期区间（全天可用） | `2026-09-24 00:00-2026-12-31 23:59` |
| C 单日 + 星期 + 时段 | `2026-10-11 05:00-2026-10-11 10:29 周日 05:00-10:29` |
| D 同上变体 | `2026-10-17 05:00-2026-10-17 10:29 周六 05:00-10:29` |

解析策略（`coupon_parser.parse_validity`）：

1. 先用 `\d{4}-\d{2}-\d{2}\s+\d{1,2}:\d{2}` 抽出所有「日期 时间」，第一个是起点、最后一个是终点；
2. 把已抽走的部分替换成空格，再从剩余文本里找 `周X` 提取星期限定；
3. 再从剩余文本里找 `HH:MM-HH:MM` 作为每日可用时段；
4. 时段列表为空 ⇒ 全天可用；`起始 > 结束` ⇒ 判定为**跨零点时段**。

### 坑 2：「优惠」字段语义不固定

| 券名 | 优惠字段 | 真实含义 |
|---|---|---|
| `9.9元中杯冰美式` | `¥9.9 (用券价格)` | 用券**价格** |
| `中薯条` | `¥0 (用券价格)` | 用券**价格**（免费） |
| `4折麦辣三件套券` | `¥4 (用券立享)` | **语义不明**——既不像价格也不像折扣额 |

处理方式：只有文本含「**用券价格**」时才把数字当作价格（`faceSemantics = "price"`）；
其他一律标为 `unknown`，改由券名中的折扣率反推到手价：

```
到手价 = 原价 × 折扣率      # 例：4 折 → 原价 × 0.4
```

**绝不要**把 `unknown` 的数字直接当成价格去算节省金额。

### 坑 3：返回体里没有券 ID

同一张券会在列表里重复出现（实测「咸蛋黄鸡腿蛋月堡」连续出现两次，内容完全一致）。
因为没有 `couponId`，无法用 ID 去重。

处理方式：用**指纹**做去重与追踪主键：

```
fingerprint = sha1(券名 + 有效期原文 + 图片URL)[:16]
```

这同时解决了三件事：去重、识别「新券」、台账长期追踪。

## 三、券商（coupon JSON）输入格式

`scripts/` 下的脚本统一吃这个结构。字段名保持与上面一致，便于手工核对。

```json
{
  "fetchedAt": "2026-10-10 17:52:07",
  "coupons": [
    {
      "name": "4折麦辣三件套券",
      "priceText": "¥4 (用券立享)",
      "validityText": "2026-10-10 00:00-2026-10-16 23:59 10:30-23:59",
      "receivedText": "今日收到",
      "tags": ["到店专用"],
      "imageUrl": "",
      "originalPrice": null
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 券名 |
| `validityText` | 是 | 有效期原文，直接复制接口返回值 |
| `priceText` | 否 | 「优惠」字段原文，含 `¥` 符号 |
| `tags` | 否 | 标签数组 |
| `imageUrl` | 否 | 参与指纹计算，建议保留原始 URL |
| `originalPrice` | 否 | **可选增强**：从 `query-meals` 拿到的门店实价，填了会显著提高节省金额准确度 |

> `originalPrice` 是本设计里唯一「上游可注入」的字段。
> 如果 agent 有能力先调 `query-meals` 匹配到商品实价，强烈建议填；
> 填不了也不会报错，会退回 `data/tiering_config.json` 的原价基线估算。

## 四、解析产出的结构化字段

`coupon_parser.parse_coupon` 输出的关键字段：

```json
{
  "fingerprint": "7bfae214b0740da1",
  "name": "4折麦辣三件套券",
  "category": "combo",
  "bogo": false,
  "facePrice": 4.0,
  "faceSemantics": "unknown",
  "discountRate": 0.4,
  "validFrom": "2026-10-10 00:00",
  "validTo": "2026-10-16 23:59",
  "weekdays": null,
  "windows": [["10:30", "23:59"]],
  "crossDay": false,
  "channels": ["pickup"],
  "channelsAssumed": false
}
```

- `windows` 为空数组 ⇒ 全天可用
- `weekdays` 为 `null` ⇒ 不限星期；否则是 `[0..6]`，0 是周一
- `channelsAssumed = true` ⇒ 券没有渠道标签，脚本按「通用」处理（分数上略保守）
