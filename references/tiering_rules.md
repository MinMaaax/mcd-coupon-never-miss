# 分级规则详解

本文件解释 `scripts/value_tier.py` 的评分逻辑，以及**怎么改**。
所有阈值都在 `data/tiering_config.json` 里，改配置不需要动代码。

---

## 一、两个正交的轴

| 轴 | 回答的问题 | 用途 |
|---|---|---|
| **价值分 V** | 这张券值多少钱？ | 决定等级 S/A/B/C |
| **紧迫度 U** | 这张券还能放几天？ | 决定排序与是否提醒 |

**为什么必须拆开：**

如果把紧迫度混进价值分，一张「只剩 1 天的 9.9 元咖啡券」会因为临期加成而被抬成极品券，
分级就失去意义了。这两件事的语义完全不同：值钱是该留意的，快过期是该行动的。

最终排序 = **先按紧迫度分桶，桶内按价值分降序，同分再按省下的钱降序**。
读出来的效果就是「我现在最该先用哪张」。

## 二、免费券硬规则（0 元券一律极品券）

**免费是一种独立性质，不参与加权打分。**

命中「免费」的券直接锁定最高等级，`valueScore` 拉平到 `1.0`，字段 `gradeReason = "free"`。
这条规则**不依赖原价基线**——原价未知也照样判极品，因为「不花钱拿到」这个事实本身不需要估价。

### 怎么算命中「免费」

`coupon_parser.detect_free()` 按以下顺序判定（返回 `freeSignal`）：

| 顺序 | 信号 | 条件 | 说明 |
|---|---|---|---|
| 1 | `face-price` | 券面写明「用券价格 ¥0」 | 最硬的证据，官方标价即 0 |
| 2 | `name` | 券名含「免费 / 免单 / 白送 / 零元 / 0元」 | 文本信号 |
| 3 | `rate-zero` | 折扣率被判定为 0 | 兜底 |

**已经排除的误判：**

- `10元` 里的 `0元` —— 用负向后顾 `(?<![\d.])0\s*元` 挡住
- `0元起` / `0元起购` —— 营销话术，不是真免费，由 `FREE_EXCLUDE_RE` 剔除
- `买一送一` —— 它是 5 折，不是免费（`BOGO_RE` 优先级更高）

### 为什么不做成「折扣分给 1.0」那么简单

因为加权求和会让免费券被**品类权重和金额上限稀释**。
实测：0 元中薯条按加权分只有 0.613（小食品类 0.4 ＋ 省 13 元未满 30 元上限），
0 元奶香大米派只有 0.520 —— 两张都会被压到 A 级。
但「不花钱拿到一份薯条」显然强过任何一张 5 折券，所以必须以硬规则锁定。

### 排序细节

免费券的 `valueScore` 全部拉平到 1.0，所以同紧迫度桶内改由**省下的钱**决定先后：
0 元月堡（省 25）排在 0 元大米派（省 8）之前。

### 关闭或调整

`data/tiering_config.json`：

```json
"freeCoupon": {
  "enabled": true,       // 设 false 则退回纯打分
  "forceGrade": "S",     // 想改成 A 也可以
  "forceScore": 1.0      // 拉平后的分值，决定同桶内排序
}
```

## 三、价值分 V 的计算

```
V = ( w_saving×S金额 + w_category×S品类 + w_discount×S折扣 + w_channel×S渠道 ) / (权重之和)
```

默认权重：`saving 1.2 ｜ category 0.8 ｜ discount 0.6 ｜ channel 0.4`（和为 3.0）

### 四个分项

| 分项 | 取值 | 说明 |
|---|---|---|
| **S金额** | `min(省下的钱 / savingCap, 1.0)`，取不到为 `0.5` | 默认 `savingCap = 30` 元，即省 30 元拿满分 |
| **S品类** | `categoryScores[品类]` | 套餐 1.0 / 汉堡 0.8 / 饮品 0.6 / 小食 0.4 / 甜点 0.3 / 酱料 0.15 |
| **S折扣** | 见下表 | 0 元 = 1.0，≤5 折 = 0.9，≤6.5 折 = 0.6，≤8 折 = 0.4，其他 0.25 |
| **S渠道** | 到店+外送通用 1.0，单渠道 0.7 | 通用券更灵活 |

### 「省下的钱」怎么来

这是全流程最容易出错的一环，所以单列一节。

```
到手价 =
    券面写了「用券价格」        → 直接用该数字
    否则券名有「N折」          → 原价 × 折扣率
    否则                        → 未知（不猜）

省下的钱 = 原价 − 到手价        （买一送一时见下）
```

**原价的三个来源，按优先级：**

| 优先级 | source | 说明 |
|---|---|---|
| 1 | `meal-price` | 上游从 `query-meals` 拿到的门店实价，最准 |
| 2 | `baseline-keyword` | `price_baseline.entries` 里的关键词匹配（取最长匹配） |
| 3 | `baseline-category` | 按品类给的兜底价 |
| — | `unknown` | 三个都没有 ⇒ `savingKnown = false`，金额分记 0.5 中性分，并在简报里明确标注 |

**关键词匹配有个坑**：基线条目可以带 `category` 字段。
不带 `category` 的条目对所有品类生效；带了就只在该品类下参与匹配。

> 实例：「巧克力味厚松饼猪柳蛋套餐」是**套餐**（原价约 35），
> 如果不加约束，券名里的「厚松饼」会命中单品的 12 元基线，
> 算出「省 −17.9 元」这种荒谬结果。
> 给「厚松饼」条目加上 `"category": "burger"` 后，套餐类券就不会误用它。

**买一送一（`bogo`）的省法：**

```
券面给了用券价格 → 省 = 原价 × 2 − 用券价
否则             → 省 = 原价（付一份的钱拿两份）
```

### 折扣分怎么算

优先用券名里写明的折扣（`discountRate`）；
券名没写但能算出到手价时，用 `到手价 / 原价` **反推**（买一送一时分母是 `原价×2`）。

**不能退回中性分。** 券面直接给了「用券价格」的券（如「9.9 元冰美式」）如果按中性 0.5 计，
会系统性低估这类券的力度。

## 四、等级阈值

| 等级 | V 下限 | 定位 | 典型券 |
|---|---|---|---|
| **S 极品券** | 0.78 | 过期前必须用掉 | **全部免费券**（硬规则）、4 折三件套、买一送一（高价品） |
| **A 精品券** | 0.50 | 优先安排 | 9.9 元早餐两件套 / 咖啡 |
| **B 普通券** | 0.35 | 有需要再用 | 4 折圆筒、麦旋风买一送一 |
| **C 渣渣券** | 0.00 | 随缘 | 冷门口味、需满额叠加的低值券 |

### 实测校准结果

用 `data/sample_coupons.json` 跑出来的分布（2026-10-10，可作为调参基准）：

| 券 | V | 等级 |
|---|---|---|
| 免费巨无霸汉堡（省 25） | 1.000 | S ← 免费硬规则 |
| 中薯条（省 13） | 1.000 | S ← 免费硬规则 |
| 奶香大米派（省 8） | 1.000 | S ← 免费硬规则 |
| 4 折麦辣三件套券（原价 40 → 16） | 0.860 | S |
| 火腿扒堡早餐两件套（原价 25 / 到手 9.9） | 0.741 | A |
| 人气麦旋风买一送一（两份 28 / 付 15） | 0.527 | A |
| 9.9 元中杯冰美式（原价 17 / 到手 9.9） | 0.508 | A |
| 巧克力味厚松饼猪柳蛋套餐（原价 35 / 到手 29.9） | 0.478 | B |
| 4 折圆筒冰淇淋券（原价 9 → 3.6） | 0.425 | B |

对比硬规则上线前：0 元中薯条 0.613（A）、0 元奶香大米派 0.520（A）——
现在都正确归入 S 级。

### 想调口味怎么办

| 你的感受 | 改哪里 |
|---|---|
| 不想让免费券自动判极品 | `freeCoupon.enabled = false` |
| 免费券想判成 A 而不是 S | `freeCoupon.forceGrade = "A"` |
| 大额券之间区分度不够 | 调高 `savingCap`（比如 50） |
| 咖啡券给太高了 | 调低 `categoryScores.drink`，或调高 S/A 阈值 |
| 整体偏严 / 偏松 | 整体平移 `grades` 里的 `min` |

## 五、紧迫度 U

| 剩余天数 | 档位 | 标签 | 行为 |
|---|---|---|---|
| < 0 | `expired` | 已过期 | 从结果中剔除 |
| ≤ 1 | `critical` | 特急 | S 级触发提醒，措辞升级为「今天最后一天 / 明天到期」 |
| ≤ 3 | `high` | 临期 | **S 级触发提醒**（默认提醒窗口） |
| ≤ 7 | `medium` | 留意 | 日历中靠前展示 |
| > 7 | `normal` | 常规 | 常规展示 |

阈值在 `tiering_config.json → urgencyDays`。

**额外字段 `usableToday`**：当券当天到期（`daysLeft == 0`）时，
脚本会比对当前时间与该券的每日时段——如果今天的时段已经全过了，标记为 `false`，
提醒用户「这张券今天已经来不及用了」。

## 六、提醒规则

| 条件 | 说明 |
|---|---|
| 等级 | 必须是 **S 极品券**（`alert_checker.ALERT_GRADES`） |
| 紧迫度 | 必须是 `critical` 或 `high` |
| 去重 | 台账记录 `alertedAt[档位]`，**同一张券同一档位只提醒一次** |

台账 `data/coupon_ledger.json` 每张券记录：
`firstSeen` / `lastSeen` / `validTo` / `lastGrade` / `lastValueScore` / `alertedAt`。

超过 90 天没再出现的券会自动从台账清理。

---

## 七、免责与口径

- 原价基线是**估算值**，不是官方标价。真实到手价以下单页面的 `calculate-price` 结果为准。
- 节省金额取不到时不猜，明确标为「金额未知」，且不参与金额评分。
  **例外：免费券即使金额未知也照判极品券**（免费是硬事实，不需要估价）。
- 本工具只做券的资产运营（领券、分类、排期、提醒），**不自动下单**。
